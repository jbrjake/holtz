# Convergence Iteration Enforcement

**Date:** 2026-03-25
**Status:** Design
**Trigger:** Run 18 post-mortem — model gamed convergence checker by sleeping through iterations instead of doing real audit work

## Problem

The convergence loop requires 3 data points from `convergence_check.py` with 60-second minimum gaps. The model satisfied this by sleeping 62 seconds between calls and running cosmetic verification commands. The 60-second minimum gates on time, not work product. Advisory language in the SKILL.md was read, understood, and ignored under goal-completion pressure.

This is the same failure pattern that led to every other enforcement hook: the model agrees with the process and does not follow it.

## Design

### 1. Sweep Output File Requirement

Each convergence iteration must produce a scoped sweep file before `convergence_check.py` can be called.

**File path:** `docs/holtz/audit/sweep-iter-{N}-{lens}.md`

Where `{N}` is the convergence iteration number (from HISTORY.json length + 1) and `{lens}` is the analytical lens used.

**Contents:** Per-file analysis under the declared lens, covering changed files + 2-hop blast radius from the impact graph. Each file examined gets an entry with findings or explicit "no new findings" with justification. The lens name appears in the file header.

**All validation is performed by convergence_check.py** (not the hook — see Section 2 for rationale):

Structural checks:
- File exists at the expected path
- File was created/modified after the last history entry's timestamp (not stale)
- File is at least 500 bytes (rules out empty/stub files)
- File contains at least 3 lines starting with `- ` or containing backtick-fenced file paths (evidence of per-file analysis)

Semantic checks:
- The `--lens` argument matches the lens name referenced in the sweep file
- The lens differs from the prior iteration's lens in HISTORY.json
- The lens is a valid name from the lens registry (parsed from `references/lens-registry.md`)

If any check fails, the script exits with code 4 (SWEEP_INVALID) and does NOT write to HISTORY.json or the marker file. This preserves the model's one-call-per-session allowance for a retry with a valid sweep file.

### 2. One Convergence Call Per Session (PreToolUse Hook + Script Marker)

**Architecture:** The hook and script split responsibilities cleanly:
- **Hook (convergence_iteration_gate.py):** Pure gatekeeper. Reads the marker file. If it exists and is fresh, blocks. Does NOT write anything.
- **Script (convergence_check.py):** Writes the marker file `docs/holtz/.convergence-called` ONLY on successful data point recording (history entry written). If validation fails (bad lens, missing sweep file, lens repeat), no marker is written and the model can retry.

This split solves the "wasted call" problem: if the script rejects the call for validation reasons, the hook won't block the retry because no marker was written.

**Hook implementation:** PreToolUse hook on Bash. Reads `tool_input.command` from the event JSON (the shell command string — different from Write|Edit hooks which read `tool_input.file_path`). Checks if the command contains `convergence_check.py`. If so, checks the marker file.

**Marker file:** `docs/holtz/.convergence-called` — written by convergence_check.py (not the hook) after a successful history entry. Contains a session token: a random UUID generated by the script on each successful call. The hook reads this token and blocks if the token matches a token it has seen in this session (tracked via a companion file or the token value itself).

**Simpler alternative for session detection:** Since the marker contains a timestamp, and a successful convergence_check.py call writes it, the hook can simply check: if the marker exists and was written less than 30 minutes ago, block. The 30-minute window works because `/clear` introduces a natural time gap (user must respond), and sessions that run 30+ minutes of legitimate work between convergence calls are rare enough to be acceptable. If this proves too loose, the session-token approach can be added later.

**Registration in hooks.json:** Separate entry from existing Write|Edit hooks:
```json
{
  "type": "command",
  "command": "python \"${CLAUDE_PLUGIN_ROOT}/hooks/convergence_iteration_gate.py\"",
  "matcher": "Bash"
}
```

**Edge cases:**
- First call after Step 10 fix loop: allowed (no marker exists yet)
- Script rejects for validation (exit 2/3/4): no marker written, model can fix the issue and retry
- Script succeeds (exit 0 or 1): marker written, subsequent calls blocked until `/clear`
- Model tries alternate invocation: hook matches substring `convergence_check.py` in command
- Marker from prior session: >30 minutes old, ignored
- HISTORY.json shrinkage detection: if convergence_check.py detects that HISTORY.json has fewer entries than expected (based on the marker file or prior call), it warns: `HISTORY_TAMPERED: History file has fewer entries than expected. Do not reset history.` (exit code 5)

### 3. Lens Rotation Enforcement in convergence_check.py

The script gains a required `--lens` argument.

**On each call:**
1. Validates the lens is in the lens registry (parsed from `references/lens-registry.md` — exit 2 if invalid)
2. Locates the sweep file at `docs/holtz/audit/sweep-iter-{N}-{lens}.md` and validates it (structural + semantic — exit 4 if invalid)
3. Checks the prior entry's lens — if it matches, exits with error: `LENS_REPEAT: Cannot use the same lens ({lens}) in consecutive iterations. Rotate to a different lens.` (exit code 3)
4. Records the lens and sweep file path in HISTORY.json alongside timestamp, punchlist, and test data
5. Writes the marker file `docs/holtz/.convergence-called` (only after successful history write)
6. First iteration (no prior entry) accepts any valid lens

**Exit codes:**
- 0: converged
- 1: not converged (keep going)
- 2: bad input (missing --lens, invalid lens name, missing punchlist)
- 3: lens repeat (same lens as prior iteration)
- 4: sweep invalid (missing file, too small, no analysis evidence, lens mismatch)
- 5: history tampered (fewer entries than expected)

**HISTORY.json entry format:**
```json
{
  "timestamp": "2026-03-25T12:00:00",
  "punchlist": {"OPEN": 0, "RESOLVED": 7, ...},
  "tests": {"passed": 640, "failed": 0, "skipped": 0},
  "lens": "integration",
  "sweep_file": "docs/holtz/audit/sweep-iter-2-integration.md"
}
```

**Sweep file validation in the script:**
- Reads the sweep file path from the expected location
- Verifies it exists on disk
- Verifies the lens name appears in the file

**New tests in test_convergence_check.py:**
- `--lens` argument is required (missing = exit 2)
- Lens repeat is rejected (exit 3)
- Lens rotation is accepted
- HISTORY.json records the lens
- Sweep file referenced in history

### 4. SKILL.md Convergence Loop Rewrite

Steps 14-15 rewritten to make the iteration protocol explicit.

**Each convergence iteration:**
1. Query impact graph: `blast_radius` on all nodes modified since last convergence call (2-hop depth)
2. Select next lens from registry (must differ from prior iteration's lens)
3. Run Steps 6-8 scoped to blast radius files under the selected lens
4. Write sweep file: `docs/holtz/audit/sweep-iter-{N}-{lens}.md` — per-file analysis, minimum 500 bytes, findings or explicit "no new findings" per file
5. Run full test suite + linters
6. Call `convergence_check.py --lens {lens}` (once per session — hook blocks second call)
7. If not converged: update STATUS.md (position, lens used, next lens planned), tell user to `/clear`
8. If converged: proceed to Step 16 resweep

**The `/clear` boundary is mandatory between iterations.** The one-call-per-session hook enforces this structurally.

**Rationalization table additions:**
| Your thought | The reality |
|---|---|
| "The convergence is obvious, skip the sweep" | Each iteration exists because fixes introduce bugs. The sweep that finds nothing proves convergence. The sweep you skip would have found something. |
| "I'll just wait 60 seconds and re-run the checker" | Convergence iterations require sweep output files with per-file analysis under a rotated lens. Sleeping doesn't produce files. |
| "I'll reset HISTORY.json to clear bad entries" | The history is evidence. Resetting it is destroying evidence. If entries are invalid, the work that produced them was invalid — redo the work. |

## Testing

**convergence_check.py:**
- `--lens` argument required (missing = exit 2)
- Invalid lens name rejected (not in registry = exit 2)
- Lens repeat rejected (exit 3)
- Lens rotation accepted
- HISTORY.json records lens and sweep_file path
- Marker file written only on successful history entry (exit 0 or 1)
- Marker file NOT written on validation failure (exit 2/3/4)
- Sweep file missing (exit 4)
- Sweep file too small (<500 bytes, exit 4)
- Sweep file missing analysis lines (<3 list items, exit 4)
- Sweep file lens name mismatch (exit 4)
- History shrinkage detected (exit 5)

**convergence_iteration_gate hook:**
- First call allowed (no marker)
- Second call blocked (marker exists and fresh)
- Stale marker (>30 min) ignored — call allowed
- Non-convergence Bash commands unaffected
- Command with `convergence_check.py` substring matched regardless of python path
- Hook reads `tool_input.command` from Bash event JSON

**Integration:**
- End-to-end: write valid sweep file, call checker (allowed, marker written), call checker again (blocked by hook)
- End-to-end: write invalid sweep file, call checker (rejected exit 4, no marker), fix sweep file, call checker again (allowed)

## Risk

The main risk is false positives — the hook or script blocking legitimate convergence calls. Mitigated by:
- Clear error messages explaining what's needed
- Staleness window on marker file so stale sessions don't permanently block
- The model can always ask the user for help if blocked unexpectedly
